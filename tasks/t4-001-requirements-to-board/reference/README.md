# t4-001 reference bundles

Two bundles live here. Only the first passes the evaluator.

## `submission/` (synthetic, passes)

No design tool or agent produced this bundle. `build_bundle.py` assembles it
from AEDL's own pieces:

- `architecture`: the t3-001 reference design, copied from the output of
  `tasks/t3-001-satcom-terminal-28ghz/reference/solve.py`;
- `element/design.yaml`: a copy of `tasks/t1-001-patch-28ghz-ro4350b/reference/design.yaml`;
- `board/patch.kicad_pcb`: antenna-cad 0.2's KiCad emitter run on that
  element spec (its UUIDs are name-derived, so the file is reproducible and
  the evaluator can regenerate it), with `board_provenance` carrying its
  SHA-256;
- `verdicts`: the t4-001 evaluator's own recomputation, with each number
  tagged by the SHA-256 of the architecture JSON or the element spec it came
  from, origin `derived`, fidelity `analytic`. ELEM-S11-IN-BAND is
  `unknown`, which is how the analytic tier recomputes it.

Because the verdicts come from the evaluator, this bundle shows that the
evaluator accepts a correct bundle and that every certifiable requirement is
closable. It does not show that any tool can produce such a bundle. The tests
in `tests/test_t4_001.py` use it as the known-good input.

Regenerate (about 20 s, runs the t3-001 and t1-001 evaluators once each):

```bash
.venv/bin/python tasks/t4-001-requirements-to-board/reference/build_bundle.py
```

## `edgearray_hero/submission/` (generated by EdgeArray, does not pass)

Generated, not synthetic: `scripts/bundle_from_edgearray.py` converted the
on-disk outputs of EdgeArray's deterministic hero workflow. It scores
verdict_agreement 0.5, actual_agreement 0.3, provenance_completeness 1.0 and
board_valid 1.0, so the task fails on it. `docs/tasks/t4-001.md` lists, per
requirement, what the hero reported, what AEDL recomputed, and why they differ.
The bundle is kept as the hero produced it. `conversion.json` beside
`bundle.json` records the source revision, artifact ids, the fields the
converter filled in, and the hero's warnings.

Commands (2026-10-11):

```bash
# EdgeArray: /Users/johnhodge/Documents/code/edgearray-studio, branch
# feat/agentic-workspace, commit 5dfd8293b1dee91c6809f4fea87be681362ac89c.
# The hero packages (workflows, core, adapters) had no local changes; the
# working tree had unrelated edits to edgearray-agent.
R=/Users/johnhodge/Documents/code/edgearray-studio
export PYTHONPATH=$(ls -d $R/python/*/src | tr '\n' ':')   # macOS hides the editable .pth files
DD=$(mktemp -d)
$R/.venv/bin/edgearray workflow hero --project aedl-hero --data-dir "$DD" --em-solver analytic
# prints: project aedl-hero  revision 0bc6b4306361
.venv/bin/python scripts/bundle_from_edgearray.py --data-dir "$DD" \
  --project aedl-hero --out tasks/t4-001-requirements-to-board/reference/edgearray_hero/submission
```

A second run into a fresh directory gave the same revision
(`0bc6b4306361bc3005341721d6fc965421ca34522cc5315774e80ec4053c8d87`) and
byte-identical payloads. `tests/fixtures/edgearray_hero/` holds the trimmed
data directory (head, revision, and the architecture, element, board and
verification artifacts) so `tests/test_bundle_from_edgearray.py` can
regenerate this bundle without EdgeArray.
